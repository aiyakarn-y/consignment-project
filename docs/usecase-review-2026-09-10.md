# ConsignmentSystem — Use-case review 10 กันยายน 2026

ผลสรุป: flow หลักของเดโมทำงานตามชุดทดสอบ แต่ยังไม่ครอบคลุมไฟล์ใหม่ การแก้ไขพร้อมกัน และการกู้คืนเมื่อข้อมูลเสียหาย ไม่ควรใช้จำนวน tests เพื่อรับรองว่าถูกต้องทุกกรณี

ขอบเขต: อ่านโค้ดปัจจุบันและข้อจำกัดเดิม ตรวจ regression และ source audit พร้อมจำลองเคสใหม่ใน TemporaryDirectory; ไม่แก้โปรแกรม ไม่ล้างข้อมูลจริง ไม่ deploy

## สถานะหลังดำเนินการ U1–U4

ดำเนินการ 4 ขั้นแรกแล้ว: ตรวจหัวคอลัมน์ Profile, เลือก/รายงานหลายชีต, แหล่งยอดสุทธิที่เลือกชัดเจน และ Master แทน fallback พร้อม Preview. ดูแผนและผลทดสอบใน `_bmad-output/implementation-artifacts/import-safety-u1-u4.md`. รายการข้อค้นพบด้านล่างเก็บเป็นหลักฐาน ณ วันรีวิวก่อนแก้; U5–U7 และหัวข้ออื่นยังไม่ถือว่าแก้แล้ว. Profile เดิมต้อง preview/resave ก่อน Import ใหม่; ไม่เปลี่ยนรายการเก่า. Multi-sheet custom profile รองรับเฉพาะชีตที่ใช้หัวคอลัมน์ตาม Profile เดียวกัน.

## Use case ที่มีการรองรับและ regression ปัจจุบันผ่าน

- อ่านตัวอย่าง5แหล่ง, normalizeราคา/ต้นทุน/GP/MG, source control totals และต้นฉบับอ้างอิง
- ส่วนลดไม่ระบุและไม่มีฐานให้default0% แก้ภายหลังได้; ส่วนลดเป็นเปอร์เซ็นต์/อัตราส่วน/จำนวนเงินและcompoundตามรูปแบบที่รองรับ
- แก้Price/Qty/Discount/Netเดี่ยวและหลายรายการ; reverseส่วนลดจากNet; immutable source reference และauditค่าที่แก้
- SKUเดียวกันรวมจำนวน/ยอด; Barcodeไม่ใช่groupingkey; exportreadyไม่ดูดแถวผิดมารวม
- signedQty, ข้อมูลผิดถูกblock, below-cost confirmation และ resetเมื่อค่าที่ใช้ยืนยันเปลี่ยน
- Excel4หัวคอลัมน์ภาษาอังกฤษ, Discount2ตำแหน่ง, ประวัติExport/ตรวจซ้ำ
- HistoryPaging, ClearHistoryพร้อมconfirm/rollback/ไม่กลับมาจากbackfill
- Clearข้อมูลนำเข้าแบบcommitก่อนcleanupและ retry; LocalFileStore atomic write/path traversal; backup/restoreกรณีไฟล์ครบและlegacy migration
- Localstartซ้ำ/พอร์ตไม่ว่างมีข้อความชัดเจน

R5จากรีวิวเก่าเรื่องClear rollbackแล้วอ้างไฟล์หายมีregressionที่แก้แล้ว จึงไม่ยกเป็นบั๊กคงค้างเดิมอีก ส่วนUploadมีrollback/cleanupเพิ่มแล้ว แต่UXการนำเข้าบางไฟล์สำเร็จบางไฟล์ผิดยังควรระบุกติกาให้ชัด ห้ามตีความว่ารายการเก่าทุกข้อถูกแก้จากการจัดworkspace
